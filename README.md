# BigQuery Agent Analytics — Looker Studio Dashboard

A Looker Studio (Data Studio) dashboard with tile-level parity to the Looker
[`agent-analytics-block`](https://github.com/looker-open-source/agent-analytics-block),
built exclusively on the flat BigQuery views generated by the
[ADK BigQuery Agent Analytics plugin](https://adk.dev/observability/bigquery-agent-analytics/).
For teams that run BQAA but do not run Looker.

**Governing contract:**
[GoogleCloudPlatform/BigQuery-Agent-Analytics-SDK#365](https://github.com/GoogleCloudPlatform/BigQuery-Agent-Analytics-SDK/issues/365)
— all scope, parity, certification, and acceptance rules live there. Changes
here are driven by M0 evidence, not speculative review.

## Design in one paragraph

The ADK plugin (`create_views=True`) generates one flat view per event type.
One embedded Looker Studio `CUSTOM_QUERY` (`sql/events_v1.template.sql`)
`UNION ALL`s the 15-view static v1 intersection (the ADK 1.27.0 inventory)
into a stable typed schema; the report's 8 pages (7 parity pages + Trace
Inspector) are built over that single data source. No SDK code, no new
persistent BigQuery objects in the user's dataset, no reads of the raw
`agent_events` table. Users hydrate the canonical template against their own
project/dataset/prefix via a Linking API URL emitted by a validating helper.

## Repository layout

| Path | What it is |
|---|---|
| `spec/dashboard_spec.yaml` | Executable parity manifest: 37 chart records, 9 non-data elements, controls, listener matrix — **generated** from the pinned block LookML, never hand-edited |
| `spec/overrides.yaml` | **The only hand-maintained spec input** — reviewed M0/M2 decision layer (oracle mappings, expected-result matrix, screenshot goldens, listener design, control placement, `call_row_policy`) merged into every regeneration by ID |
| `spec/dashboard_spec.schema.json` | Full record contract (draft-07, closed records) validated in CI |
| `sql/events_v1.sql.tmpl` | Reviewed logical union query (**generated** by `tools/gen_events_tmpl.py`) |
| `sql/events_v1.template.sql` | Sentinel-rendered SQL embedded in the canonical report (**generated** by `tools/render_template.py`) |
| `sql/preflight.sql.tmpl` / `.template.sql` | Structural compatibility check, run by the hydration helper before emitting a link |
| `bindings/template_bindings.yaml` | Executable sentinel bindings (real fixture identifiers, not placeholders) |
| `tools/lookml_to_spec.py` | Manifest generator (pinned block commit → spec) |
| `tools/gen_events_tmpl.py` | Union-query generator (ADK 1.27.0 inventory → tmpl) |
| `tools/render_template.py` | Deterministic tmpl → template renderer with sentinel-uniqueness checks |
| `tools/validate_spec.py` | CI assertions over the manifest (counts, listener matrix, defaults) |
| `tools/capture_inventory.py` | Observed-inventory capture + normalized fingerprint (provenance rule) |
| `tools/seed_events.py` | Deterministic synthetic seed generator with all contract fixtures |
| `oracle/` | Parity oracle (M0 artifact — see `oracle/README.md`) |

## Publication safety

Everything in this repository is synthetic. Never commit production project
IDs, credentials, service-account keys, trace/user identifiers, prompts, tool
arguments/results, or error payloads. CI runs secret scanning; benchmark raw
results must be sanitized before commit.
